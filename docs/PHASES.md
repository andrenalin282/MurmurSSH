- Phase 11.0 (v1.5.0): Background transfer queue + multi-connection. New `transfer_queue` service (services/transfer_queue.rs): one dispatcher thread (`Mutex<QueueState>` + `Condvar`) promotes Queued→Active jobs up to `max_concurrent_transfers` (Settings, default 2, clamp 1–8 via `models/transfer.rs::clamp_concurrency`), spawning one worker thread per job — each worker opens its own SFTP/FTP session for true parallelism. Per-job cancellation via `Arc<AtomicBool>` replaced the deleted profile-keyed `transfer_cancel`; the low-level transfer fns in `sftp_service`/`ftp_service` now take `cancel: &dyn Fn() -> bool` (workspace edit-flow passes `&|| false`). New model `models/transfer.rs` (`TransferKind`/`TransferState`/`TransferJobView`, `CANCELLED_ERROR`, `clamp_concurrency`). New commands `commands/transfer.rs`: `enqueue_transfer`/`cancel_transfer(job_id)`/`cancel_all_transfers`/`list_transfers`/`clear_finished_transfers` + `local_path_is_dir`; the old `Channel`-based transfer commands (`upload_file`/`download_file`/`download_file_to`/`upload_directory`/`upload_path`/`download_directory`/`cancel_transfer(profile_id)`) were removed (`upload_file_bytes` kept for New File). Queue emits a global `transfer-update` event (one `TransferJobView`); `transfer_queue::init(&app)` wired in `lib.rs` `.setup`, and `cancel_all()` added to `cleanup_on_exit`. Frontend: new `TransferQueuePanel` (src/components/transfer-queue.ts) renders jobs from events with in-place row updates (full re-render only on structural change — add/remove/state change) plus per-job/cancel-all/clear-finished controls; `file-browser.ts` transfer methods resolve overwrites/destinations then `enqueue` (single-progress-bar machinery removed; `disconnect()` no longer cancels — the queue is independent); Settings dialog gains a concurrency input; i18n in all 6 locales (`transferQueue.*`, `fileBrowser.queuedCount`, `settings.maxConcurrentTransfers[Hint]`). Dispatcher correctness (Opus-reviewed): settings read + event emit happen OUTSIDE the queue lock, and the `cv.wait` is predicate-guarded under the lock (closes a lost-wakeup window), plus a worker `catch_unwind` panic guard. Reviews: per-task spec + quality + Opus final holistic (which caught and fixed the lost-wakeup regression) = SHIP. Build: cargo/clippy/tsc/vite green, 9 lib tests pass.

- Phase 13.0: Launch-a-profile, parallel windows, desktop shortcuts & group accordion. New `launch_service` (services/launch_service.rs) + `commands/launch.rs`: captures a `--profile <id-or-name>` CLI arg at startup into a `OnceLock` (`capture_launch_arg` first line of `lib.rs run()`), resolves it by exact id then case-insensitive name (`resolve_profile_id`), and exposes `get_launch_profile`/`open_profile_in_new_window`/`create_desktop_shortcut`/`get_desktop_dir` commands. **Parallel connections**: while connected, selecting a *different* profile swaps the Connect button for "Open in new window" (`ProfileSelector.updatePrimaryButtons`, gated on `selectedId !== connectedId` — `setConnected(true, id)` now carries the id), which spawns a second independent process via `current_exe() --profile <id>`. **Auto-connect on launch**: `main.ts` refactored `onConnect` into a hoisted `connectToProfile()`, reused by the `init().then` launch block. **Desktop shortcuts**: right-click a profile row → context menu (reuses `.lb-context-menu`) → "Create desktop shortcut" opens a native Save-As dialog (`@tauri-apps/plugin-dialog` `save()`, defaults to the locale-aware desktop dir via `get_desktop_dir`/`xdg-user-dir DESKTOP`, e.g. ~/Schreibtisch); backend writes the `.desktop`, `chmod 0755`, and marks it trusted (`gio set metadata::trusted true`) so GNOME runs it on double-click; `Exec` prefers `$APPIMAGE` over `current_exe()` so AppImage launchers don't point at an ephemeral mount. **Group accordion**: replaced `collapsedGroups: Set` with a single `expandedGroup: string | null` (one group open at a time, `""`=ungrouped vs `null`=none via `?? null`), persisted in settings as `expanded_profile_group` and restored on launch. Two bugs fixed during testing: orphaned context menu on re-render (hide it at the top of `render()`), and **context-menu items not clickable** (the outside-close `mousedown` listener fired for clicks *inside* the menu, removing it before `click` — guarded with `contains(e.target)`, mirroring local-file-browser). Reviews: per-task spec+quality + final holistic = SHIP. cargo/clippy/tsc/vite green, 21 lib tests (8 new launch_service). Website (MurmurSSHWeb) updated: new "Parallel connections and launchers" home card + `window` icon, profiles card → accordion wording, murmur highlights (+parallel windows, +desktop launchers/--profile).

- Phase 15 (Tasks 1–14, copy-dnd-terminal-keyboard branch): Safe uploads, terminal selection, remote copy, full keyboard navigation, shortcut audit. Safe uploads (SFTP+FTP, transfer_paths.rs): uploads now write to a hidden part_path() (/a/b/file.txt to /a/b/.file.txt.murmur-part) and rename into place only on success — a failed/cancelled upload never deletes or truncates the existing remote file; folder uploads continue past per-file errors and report an N-of-M-entries-failed summary; LoopGuard prevents infinite recursion through a symlink cycle; local root is validated before a folder upload starts. Dialogs: central Enter/Esc handling in src/components/modal-keys.ts (installModalKeyHandler, capture-phase) — Escape clicks [data-modal-cancel], Enter clicks [data-modal-primary] unless focus is a textarea/select/button; the host-key dialog has no primary action — focus starts on Cancel; there is no Enter-to-trust action. Terminal selection (services/terminal_service.rs, commands/ssh.rs::list_terminals): auto-detects $TERMINAL, x-terminal-emulator, gnome-terminal, ptyxis, kgx (GNOME Console), konsole, xfce4-terminal, kitty, alacritty, foot, wezterm, xterm, or runs a user-supplied custom command; new Settings fields terminal / terminal_custom_command; fixes SSH launch on Arch and other non-Debian distros lacking x-terminal-emulator; passphrase/password terminal flows unchanged. Local panel (src/components/local-file-browser.ts): multi-select + folder dragging via src/components/list-selection.ts; dropping onto a folder row (local→remote, remote→local, and OS file manager→remote) targets that folder; new backend commands create_local_dir / delete_local_path (services/local_service.rs) reject dot and dot-dot segments, refuse /, $HOME, and any ancestor of $HOME (via canonicalize() of the parent + is_protected()), and a symlink target removes only the link, never what it points to. Copy to… (remote, job kind remoteCopy, services/remote_copy.rs): prefers a server-side cp -a over an SSH exec channel opened on a pty (so cancelling hangs up the command instead of orphaning it); an exec-capability probe with a 10s timeout is cached per profile (forget_profile() clears it on disconnect) so repeat copies skip the probe; falls back to download+upload through ~/.config/murmurssh/workspace/.copy-tmp/<pid>-<job> (0700 perms) when exec is unavailable or times out; FTP always uses the fallback path; temp dirs are cleaned per-process on exit and stale ones are swept at startup. Keyboard (src/shortcuts.ts + src/panel-focus.ts): a single SHORTCUTS registry drives both key matching (matchShortcut) and the generated Help-dialog table (shortcutHelpHtml) — Tab switches panel focus; remote panel gained arrows/Shift-extend/Home/End/PgUp/PgDn/Enter/Backspace/Alt+↑/Ctrl+L/F2/F5/F6/F7/Ctrl+Shift+N/Ctrl+N/Delete/Ctrl+A/Ctrl+Shift+C/Ctrl+C/X/V (internal clipboard)/Ctrl+D/F11/Esc/type-ahead; local panel gained the same navigation plus F2/F7/Delete/Ctrl+U; F1/? opens help globally. Single refresh point: main.ts's transferQueue.setOnJobFinished is now the only place a completed transfer triggers a panel refresh (remoteCopy refreshes the remote panel). Task 14 shortcut audit: every key handler outside modal-keys.ts was checked against SHORTCUTS; the two gaps found were the path-input Enter/Escape handlers in file-browser.ts and local-file-browser.ts (matched ad hoc, not through matchShortcut) — added as pathEnter/pathEscape, displayOnly true, under the panels scope, with i18n in all 6 locales. Also fixed in this phase: nine localBrowser.* i18n keys used in code (ctxOpen, ctxEdit, ctxUpload, ctxRename, openFailed, renameTitle, renameFailed, uploadConfirmMsg, uploadConfirmTitle) were missing from all 6 locales, showing raw keys in the local context menu and upload-confirm dialog; a 4-space indentation bug on fr.ts's language block; and a flaky transfer_queue::tests::cancel_queued_marks_cancelled (three tests share one process-global queue singleton and raced under cargo's parallel test runner) — fixed with a module-level static TEST_LOCK: Mutex<()> held for each test body. cargo build/clippy(-D warnings)/test --lib and tsc/vite all green.
- Phase 16 (v1.9.0, released 2026-11-01): Token-gated AI access via MCP — see docs/ai-access.md.
